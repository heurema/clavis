Five slices plus integration and release. Each slice has an implementation task and a separate independent acceptance review; a reviewer never approves their own implementation. Every slice leaves a green tree, including the dead-code check, so nothing is added before something calls it. Slices run in order: 2 needs the home from 1, 3 needs the target from 2, 4 needs the configuration writer's reader and the storage reader from 1 and 2, 5 documents all of them.

Estimates (handwritten production / tests): slice 1 70–110 / 70–110; slice 2 150–200 / 150–220 plus a sweep of tests that reach servers through `CLAVIS_SERVER_URL` (four test files, about ten sites); slice 3 40–60 / 40–80 plus a sweep of exact text expectations; slice 4 180–240 / 180–260; slice 5 SKILL.md 20–35, drift test 15–30, README 40–60, PRD 2, smoke 30–50. Slices 3 and 4 cross the six-file rescoping signal: slice 3 because the first text line touches every text-output test file (the sweep goes through one helper and is reported separately), slice 4 because the five commands, their writer and their renderers are one coupled behaviour. Neither is split further. No database is needed except for the integration checks.

Test isolation for every slice: the `cliHome` helper in `internal/cli/auth_test.go` and the subprocess environment in `subprocess_posix_test.go` set `HOME` and clear `CLAVIS_HOME`, `CLAVIS_PROFILE` and `CLAVIS_SERVER_URL` before setting what the test needs, so a developer's own configuration never leaks in. `CLAVIS_SERVER_URL` stays cleared after slice 2 removes its readers, so a regression that reads it again cannot pass on a developer machine that still exports it.
