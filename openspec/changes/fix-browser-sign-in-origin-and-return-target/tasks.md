## 1. Origin-preserving documents and a URL-carried return target

Requirements: local-authentication "Protected browser authentication" (delta: the referrer-policy rule, the refusal rule and both new scenarios, with the existing return-target scenarios kept green). Design decisions 1–3. Owned paths: `internal/web/auth_view.go` (failure text), `internal/server/auth.go` (`authorizePage`, the `/authorize` and `/login` timeout fallbacks, `loginBrowser`, `loginFailure`, the `fields` arithmetic), `internal/web/auth.templ` and `internal/web/auth_models.go` (the form action replaces the hidden field), generated templ output, `internal/server/auth_test.go`, `internal/server/authorize_test.go`, `internal/server/database_test.go`. Verify: `go test -race -p 1 -count=1 ./internal/server/ ./internal/web/`; `make check`; `make smoke`.

- [ ] 1.1 Set `Referrer-Policy: strict-origin` on the authorize, invalid-link and sign-in documents, keeping `no-referrer` on the Approve 303, with a comment naming the opaque-origin failure it prevents (decision 1). Move the return target into the form action and have `loginFailure` derive it from the request URL (decision 2); drop `LoginModel.Next`, drop the `next` case from the body's field count, and delete the now-unneeded body-before-refusal reasoning. Tests: every refusal of `POST /login?next=<link>` (bad origin, `Authorization` header, wrong media type, duplicate session credentials, invalid input, wrong credentials, throttling, unavailable service, timeout fallback) renders a document whose form action carries the rebuilt link; a successful sign-in posted from such a document redirects to the link; an invalid, absent, repeated or oversized `next` renders a bare `/login` action and still refuses nothing else; `next` in the body is now an unknown field and is refused; the authorize, invalid-link and sign-in documents assert `strict-origin` while the Approve redirect asserts `no-referrer`; a POST carrying `Origin: null` is still refused with 403 everywhere; the refused-credentials, refused-origin, throttled and unavailable documents each carry exactly one failure sentence and no cleared-password line (decision 4).
- [ ] 1.2 Independent acceptance review: run the verifications; confirm no path that renders the sign-in document can omit a target the request carried, including the timeout fallback; confirm the refusals still issue no session, set no cookie and call no service; probe `next` with an absolute URL, `//evil`, an encoded newline, `%2e%2e`, a second value and 8 KiB of padding, and confirm nothing but a rebuilt link reaches the action or any header; confirm `strict-origin` withholds path and query from `Referer` by reasoning over the header's definition and by checking no document sends its URL anywhere; kill hand mutants of the policy value and of the target derivation; record the revision and line counts with generated output separate.
