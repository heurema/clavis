Four slices plus integration and release. Each slice has an implementation task and a separate independent acceptance review; a reviewer never approves their own implementation. Every slice leaves a green tree, including the dead-code check, so nothing is added before something calls it. Slices run in order: 2 needs the session columns and the `cli_authorizations` table from 1, 3 needs the token route from 2, 4 documents all of them. The JSON password route stays until slice 3, because until then the CLI and the scripts sign in through it; slice 3 removes the route, the CLI flags and moves the scripts in the same commit so no revision is left without a way to sign in.

Estimates (handwritten production / tests): slice 1 150–220 / 200–300 plus the chart and a sweep of tests that construct `NewLocalAuth` or set `CLAVIS_SESSION_TTL`; slice 2 220–300 / 250–350 plus two templates; slice 3 200–280 / 220–320 plus a sweep of tests and scripts that sign in with a password; slice 4 SKILL.md 10–20, drift test 0–20, README 30–50, PRD 2–4, `.env.example` 3. Slices 1, 2 and 3 cross the six-file rescoping signal because the migration, sqlc output, store, contracts, handlers and templates of one behaviour move together; generated sqlc and templ output is reported separately. None is split further.

Database suites use `clavis_backend_test` on port 5432. Long suites run detached under `caffeinate`.
